# Перевірка LogQL на зразках даних

Python 3.10+ і Docker, без сторонніх Python-пакетів. Скрипт нічого не запускає самостійно. Він надсилає синтетичні журнали, тому використовуйте лише окремий тимчасовий Loki, а не робоче сховище.

Із кореня репозиторію, за вільного порту `43107`:

```sh
docker run --rm -d --name csm-query-loki -p 127.0.0.1:43107:3100 grafana/loki:3.7.8
```

Контейнер використовує вбудовану конфігурацію Loki. Дочекайтеся відповіді `ready` від `http://127.0.0.1:43107/ready`, тоді запустіть:

```sh
python testing/query-check/check_queries.py --loki-url http://127.0.0.1:43107 --require-nonempty --report query-results.json
```

Адресу також можна передати змінною середовища `LOKI_URL`. Для віддаленого Docker bind-порти належать віддаленій машині: запускайте скрипт там або використовуйте SSH-тунель. Копії файлів для bind-mount також мають бути на віддаленій машині.

Перевіряються всі LogQL-вирази дашбордів і правил Grafana. `ok` означає непорожній результат без помилок розбору, `empty` - коректний запит без збігів, `error` - помилку API, синтаксису чи конвеєра. Звичайний запуск завершується ненульовим кодом за `error`; `--require-nonempty` також вважає помилкою `empty`. Для зразків репозиторію всі запити мають повертати `ok`. Це перевірка сумісності запитів із форматом даних, а не доказ виявлення всіх атак чи працездатності джерел Windows.

Додаткові вирази з уроків можна передати через повторюваний параметр `--extra`: UTF-8 файл з одним повним LogQL-виразом на рядок, коментарі починаються з `#`. Також підтримується JSON-масив рядків або об'єктів `{"name":"назва","expr":"вираз"}`. `--var host=LAB-DC01` задає конкретне значення змінної Grafana. Типові `$__range`, `$__interval` становлять `5m`, `1m`; невідомі змінні спричиняють помилку, а не тиху підстановку.

Файли `samples/<job>.jsonl` містять об'єкти `{"labels":{...},"line":"..."}`. Значення `line` надсилається без перетворень; поточний час встановлюється лише як час запису Loki. Windows - серіалізований JSON Alloy `loki.source.windowsevent`, `event_id` є числом, `event_data` є рядком InnerXML; є обидва стилі лапок XML. Немає вигаданих полів верхнього рівня `image`, `source_ip`, `logon_type`. Linux-файли містять звичайні рядки syslog/auditd, journal - лише `MESSAGE`, а не JSON. Зразки враховують відмінності міток `host` і `instance`, `auth`/`secure`, `kern`/`kernel`, `syslog`/`syslog-file`/`messages`. Події змін AD 5136/5137/5141 надходять із каналу `Security` з `job="windows_adds", category="ad_changes"`; помилки Directory Service залишаються в окремій категорії того самого job. Фаєрвол надсилає зміни правил/конфігурації 2003-2006, а не відкинуті пакети 5152/5157.

Зразки навмисно синтетичні, без реальних облікових даних. Структуру звірено 2026-10-21 з конфігураціями репозиторію та [Alloy formatLine v1.16.1](https://github.com/grafana/alloy/blob/v1.16.1/internal/component/loki/source/windowsevent/format.go). Перевірка не розгортає Prometheus і не перевіряє PromQL.

Після роботи видаліть тимчасовий контейнер разом із його даними:

```sh
docker stop csm-query-loki
```

Завдяки `--rm` контейнер буде видалено автоматично; постійний том не створюється.
